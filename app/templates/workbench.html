What PreFlight is, in plain language

What it is

PreFlight is a local, read-only review tool for a Guidewire-style insurance codebase before a cloud migration. It reads a snapshot, groups the code into features, and shows what each claim is based on, what is still unknown, and what a safe change would touch.

It runs on this machine. It never edits the source and never deploys.

What it is not

  • Not an official Cloud Assurance result, score, or certification.
  • It does not convert products to APD, and it does not replace Cloud Retrofit.
  • Not a deployment tool or a live tenant connection.
  • Not an autonomous approver. Every draft, mapping, and patch stays pending.

Three promises

  • Every claim has evidence. Each finding resolves to a file and line/pointer, or is labelled unresolved.
  • Every unknown has a name. Missing sources become explicit gaps and assumptions with an owner and impact.
  • Every change waits for a human. Agents draft; a person accepts, rejects, edits, or defers.

The five agents, one line each

  • Scout reads the snapshot, maps the code, and scopes the feature.
  • Architect drafts the target files, patches, and cloud configuration.
  • Guardian runs the deterministic checks and opens human gates.
  • Critic independently tries to break the result and records residual risk.
  • Scribe seals the bundle in the feature loop; in the codebase loop the same role is called Planner, which compiles and seals the report.

Both loops use the same first four roles. Only the sealer changes name: Scribe in the feature loop, Planner in the codebase loop.

Machine check vs human gate. Guardian opens human review gates. Critic runs independent machine checks; a Critic pass is not a gate.
