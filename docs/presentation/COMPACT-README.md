## Design and evidence constraints

- Self-contained HTML: inline CSS/JS, system fonts, no external fonts, scripts, styles, CDNs, or network calls.
- One embedded evidence image (base64 PNG, from `assets/agents/case-studies-outcome-strips.png`); hidden at 390 px. The HTML has no external file dependency.
- No over-the-top motion: 8 px fade/translate, a gentle agent-dot pulse, and a connector shimmer; all animation collapses under `prefers-reduced-motion`.
- Slide 9 is dark on screen and switches to a light, border-led theme in print; the footer uses dark text on white plus a bordered boundary badge when background graphics are off.
- Every slide footer repeats: **Official Cloud Assurance: not run**.
- The deck uses synthetic fixtures only. It does not contact a tenant, compile Gosu/Java against Guidewire, generate real Cloud API endpoints, deploy, migrate data, or run official Cloud Assurance.
- Test count is deliberately **“current pytest suite”** with **520 passing at this snapshot**.
- The audit head on slide 8 says **read live** because the run store changes when reviewer decisions are made; the presenter must read the head from the live `verify-audit` output.

## Handoff notes

The compact slide 9 remains self-sufficient if the companion page is not published with the handout.
2. **PDF is untagged.** Chromium's print output is visually correct and 12 pages, but it is not a tagged PDF. The task did not require tagging.
3. **The PDF is a point-in-time render.** Regenerate it if the HTML changes. The validation JSON records the current PDF SHA-256, byte count, and page size.
4. **No real-estate or official-assurance claim is made.** The deck intentionally stops at Stage 1 of the proof ladder. A real migration would require a real read-only snapshot, compile/test in a Guidewire developer environment, official Cloud Assurance, named SME sign-off, and production cutover with rollback.
